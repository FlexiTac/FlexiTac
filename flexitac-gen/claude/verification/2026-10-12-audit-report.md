## 0. 结论摘要

### 0.1 总体判断

`fpc_agentic_customization` 目前是一个**本地运行、结果确定、只用 Python 标准库的参数化配对 FPC 生成器**，一次生成行电极板和列电极板两块。

- **没有 agent 能力**：目录名里有 "agentic"，但运行时不包含任何 agent 或 LLM。
- **引擎计算准确，问题在检查范围和导出环节**：核心几何引擎内部的数值计算是准确的，但 DRC 检查的范围和 Gerber 导出这两个环节，有多处缺陷会直接导致做出坏板。
- **系统给出的"通过"不可信**：引擎、预览和 UI 对这些情况全都显示"通过"。

**结论：当前导出的 Gerber 不能用来下单。**

### 0.2 最需要马上知道的四件事

1. **导出的连接器焊盘位置是错的（C1）。** 〔2026-10-13 已修复，见第 8 节〕
   - 在 UI 里选 "Connector side: Top"，两块板的 44 个触点全部与走线断开。
   - 默认设置下，焊盘离相邻网络只有 0.073 mm，低于 JLC 的工艺能力，并且大约一半的触点面积被覆盖膜盖住。
2. **列板最外侧的电极贴着板框（C2）。**
   - 默认 32 列时距板框 0.155 mm，16 列及以下只有 0–0.04 mm，1 列时为 0。
   - 覆盖膜开窗开到了板外。
3. **列板的铜到板边规则本身就低于 JLC 要求（H3）。** 规则是 0.2 mm，JLC 要求 ≥ 0.3 mm；只改 profile 修不好。
4. **尾部与阅读板上的连接器不匹配（C3）。**
   - 32 路列板尾部宽 17.3 mm，THD0515 要求 16.5 ± 0.07 mm，超出公差 0.73 mm，插不进去。
   - 触点长 1.4 mm，两种连接器分别要求 ≥ 3 mm 和 4 mm。
   - 12 路行板尾部与阅读板上的 16 路行连接器路数不符。

### 0.3 其他高优先级问题

## 2. 当前实现

### 2.1 定位："agentic" 目前只是名字

- **运行时没有 agent**：应用没有任何 LLM、agent、MCP 或对话代码，所有 import 都来自 Python 标准库。页面横幅直接写着 "LOCAL · DETERMINISTIC · NO AI API"。
- **"agentic" 指的是开发方式**：项目是和 Claude 协作写出来的，导入提交带 `Co-Authored-By`，`claude/` 目录下是编码 agent 的交接文档。
- **计划中的 agent 能力只有一项**：`docs/IMPLEMENTATION_PLAN.md` 的 Phase 4，即一个可选的自然语言助手，只负责填写可见表单或解释结果。它不得决定几何、不得豁免 DRC 错误、不得改动制造文件，并且每次都需要用户确认。目前未实现。
- **仓库根目录的 `PCB-Agent-Teams-main.zip`** 是第三方的 KiCad 10 + Claude Code skills 刚性板流水线，采用 PolyForm 非商业许可。它与本应用没有任何集成，在本机也跑不起来（需要 KiCad 10），其 Gerber 检查器也不适用于 FPC。仓库中只有 FlexiTac 阅读板项目留有它的输出。

因此，本报告所说的"这个功能"，实际是一个**本地、确定性、参数化的配对 FPC 生成器**。

  3 validate_design()         输入规则（28 个错误/警告码）

### 2.3 输入模型与校验

规范输入为 `tactile-fpc-design/v1`，目前只实现了模板 `generic_matrix_v1`：

| 字段 | 含义 | 校验 |
| --- | --- | --- |
| `matrix.rows` / `columns` | 行 / 列数 | 必须是整数，范围 1–64 / 1–32（布尔值和浮点数都会被拒绝） |
| `matrix.pitch_x_mm` / `pitch_y_mm` | 节距 | 0.6–10 mm |
| `matrix.taxel_width_mm` | **列**电极宽度 | 大于 0，且宽度 + 0.25 ≤ 节距；占空比超过 0.8 时给出警告 |
| `matrix.taxel_height_mm` | **行**电极宽度 | 同上 |
| `tail.top_length_mm` / `bottom_length_mm` | 物理上层 / 下层 FPC 的尾长 | 7–80 mm |
| `tail.row_side` / `column_side` | 两块板各自的尾部方向 | bottom / top / left / right，两块板独立 |
| `role_mapping.top` / `bottom` | 哪块板放在叠层上方 | rows 和 columns 各出现一次 |
| `channel_order.rows` / `columns` | 扫描顺序 | ascending / descending |
| `project_name` | 名称 | 非空，不超过 80 字符 |

另有两条规则：

- 列数超过 16 时，`E_DUAL_LANE_WIDTH` 检查板体宽度是否放得下双 bank 加槽。
- profile 自检：`焊盘节距 − 线宽 ≥ 0.246`，以及硬编码的焊盘间距 ≥ 0.2。

默认设计为 12 行 × 32 列，节距 2.0 mm，电极宽 1.4 mm（单个 taxel 1.4 × 1.4 mm），上层尾长 12 mm、下层 7 mm，两块板尾部都朝下，role_mapping 为 top=rows、bottom=columns。

UI 只暴露了 API 的一部分：

- **共享的选项**："Connector side" 只有 Bottom/Top 两项，且两块板共用；"Scan order" 也由两块板共用。
- **UI 没有的选项**：left/right 方向、两块板分别设方向、每块板分别设扫描顺序。

### 2.5 行板几何（`engine/core.py:439-516`）

- **有效区**：
  - 宽 = (C−1)·pitch_x + 列电极宽 = 63.4 mm
  - 高 = (R−1)·pitch_y + 行电极宽 = 23.4 mm
- **连接器与尾部**：
  - 焊盘总跨度 = (R−1)·0.5 + 0.3 = 5.8 mm
  - 通道宽 = 尾部宽 = 跨度 + 2×0.75 = 7.3 mm
  - 尾部位于左下角（x 0–7.3，y −L–0）
- **板体**：72.2 × 24.9 mm。外形是 6 个顶点的简单多边形，尾部与板体共用左边。默认整板 72.2 × 36.9 mm。
- **焊盘（中心语义）**：x = 0.75 + (i−1)·0.5 + 0.15，y = −L + 0.75 + 0.7。归一化后 y = 1.45，x 从 0.9 到 6.4。
- **走线**：每条是 L 形，共 3 个点：从焊盘顶边竖直上到该行中心，再水平接到电极左缘。逻辑第 1 行在最上方，走最左侧的道，形成不交叉的阶梯。
- **补强片**：[0.25, 7.05] × [0.25, 11.75]。
- **默认 DRC 测量值**：最小线间距 0.246 mm；走线铜到板边 0.773 mm。

### 2.6 列板几何（`engine/core.py:527-750`）

- **板体**：(有效区宽 + 1.5) × (有效区高 + E + 1.5)。列数大于 16 时 E = 16，否则为 0。默认 64.9 × 40.9 mm，有效区原点在 (0.75, 0.75+E)。
- **尾部**：宽 = (C−1)·0.5 + 0.3 + 1.5 = 17.3 mm，水平居中（tail_x = 23.8）。
- **单 bank（≤16 列）**：一组 1.2 mm 节距的 deck 居中排列。过渡段用 smoothstep 曲线（16 段），高度固定（入口约 7.375 mm）。
- **双 bank（17–32 列）**：
  - 左右两组走线，分别为 ⌈C/2⌉ 和 ⌊C/2⌋ 路，线距 0.6 mm，夹着中央槽。
  - 槽高 = clamp(0.3·有效区高, 1.5, 4)，默认 4 mm。
  - 槽宽 = max(4, min(12, 板宽 − 2·(bank 跨度 + 1.5)))，默认 12 mm，归一化后位于 [26.45, 38.45] × [23.75, 27.75]。
- **每条走线的路径**：焊盘顶 → 尾部竖直主干 → 16 段线性合并段 → deck 竖直段 → 16 段线性入口段 → 电极底边中点，默认共 35 个点。入口段高 16 mm、合并段高 16 mm、扇出段高 7 mm，**都不随节距变化**。
- **外形**：
  1. 从 [0, active_y] 出发；
  2. 沿 COL_01 完整路径的"逐顶点法向偏移 0.385 mm"（0.345 + 0.04）逆向走下来；
  3. 到 [tail_x, merger_base]，绕过尾部矩形；
  4. 沿右侧对称的偏移线向上；
  5. 经 [bw, active_y] → [bw, bh] → [0, bh] 闭合。

  默认有 76 个顶点，整板 64.9 × 70.9 mm。偏移由 `_offset_polyline_away_from_x` 计算：每个顶点沿"后一点减前一点"方向的法线移动固定距离，没有任何斜接（miter）或倒角处理。
- **补强片**：尾部加合并段的矩形，内缩 0.25 mm，为 [24.05, 40.85] × [0.25, 22.75]，即 16.8 × 22.5 mm。
- **默认 DRC 测量值**：最小线间距 0.196332 mm（COL_01 与 COL_02 在合并段起点处）；走线铜到板边 0.205897 mm；到槽 0.623 mm。

### 2.7 尾部方向与物理分配

- **尾部方向**：`_apply_tail_side` 把**整块板**（电极、焊盘、开窗、补强片都包括在内）按 1/4 圈旋转，然后平移到 (0,0)。焊盘保持中心语义，奇数次旋转时交换宽和高。也就是说，"尾部方向"并不是在固定的电极方向下重新布线，而是把整块板转过去。
- **物理分配**：`role_mapping` 决定哪块板标为 top 或 bottom（例如 `top_rows_fpc`），尾长按物理层位选取。
- 两块板之间没有任何共同装配坐标系或互相垂直的校验。

### 2.8 生成后 DRC（`_verify_board_geometry`，`engine/core.py:1026-1241`）

**检查的内容**（只针对走线）：

1. **不同网络走线之间的间距**：精确计算线段距离，用包围盒剪枝。列板要求 0.17 mm，行板 0.246 mm。
2. **板内包含**：走线顶点必须在外形内，且走线不与外形边相交。
3. **中心线到板边**：行板要求 ≥ 0.75 mm；列板要求 ≥ 0.127 + 0.2 = 0.327 mm，并带 0.005 mm 容差。
4. **到槽的间距**：沿用线间距规则。

**不检查的内容**：电极、焊盘、覆盖膜、补强片、外形是否简单、缺口或尖角、网络连通性，以及**实际导出的 Gerber**。

**计算量**：列板默认 1088 个线段、573,376 个线段对，耗时约 1.07 s，占整个生成时间的 99%。

**正确性**：引擎自己计算的数值是对的，与独立 shapely 计算结果的误差不超过 1e-6 mm；基础几何函数经 20 万次随机比对，误差不超过 8.3e-6 mm。问题不在"算错"，而在"该查的没查"。

### 2.9 预览

- **SVG 生成**：`_svg_for_board` 把引擎的毫米坐标（Y 轴向上，即 Gerber 坐标系）原样写进 SVG（Y 轴向下）。viewBox 取外形包围盒外扩 1 mm，没有做 Y 翻转；焊盘在这里换算成左下角。
- **视图**：
  - "Flexible 3D" 只是 CSS 变换：`rotateX(56deg) rotateZ(-22deg)`，不模拟厚度和弯曲。
  - 装配视图把行板放在 Z=0，列板放在 `translateZ(32px)` 并做 `rotateY(180deg)`。图例和标题文字是写死的。
- **其他**：没有缩放和平移，不显示任何 DRC 数值。

### 2.10 导出（`exporters/direct_gerber.py`）

每块板一个 ZIP，包含 5 个成员：

| 成员 | 内容 |
| --- | --- |
| `Gerber_TopLayer.GTL` | 走线用 C0.254 光圈描线（D01）；电极和焊盘都用 G36/G37 区域，经 `_rect_points` 按"左下角"语义生成，**焊盘坐标问题就出在这里** |

## 3. 问题清单

编号规则：C 为严重，H 为高，M 为中，L 为低，I 为信息。每条后面括号里是各维度的原始编号，原始证据可在 `/tmp/fpc_audit/orchestrator/results/` 中按编号查找。"验证"一项给出独立复核的结论。

### 3.1 严重（Critical）

#### C1 导出 Gerber 的连接器焊盘坐标错误：选 "Top" 时全部开路；默认朝向下焊盘到相邻网络只有 0.073 mm 〔已修复〕

- **状态**：2026-10-13 已修复，导出器 0.1.1，复查通过，详见第 8.1 节。下文保留缺陷的原始记录。
- **来源**：GEO-1、DRC-2、GERBER-1/2、SWEEP-1、TESTS-2/3、UI-2、REF-2、VERIFY-UI-1、VERIFY-DRC-1、VERIFY-AGENT-1、VERIFY-SWEEP-1。是对 10-11 审查第 1 条的细化，严重性大幅上调。
- **验证**：全部确认。多个 agent 分别用自写解析器、gerbonara 和 shapely 独立复现；编排者另写脚本再次复核。
- **位置**：`exporters/direct_gerber.py:197-198`、`:273-278`；`engine/core.py:1358-1367`、`:881-885`；`web/index.html:50`
- **机制**：
  - 引擎按**中心**存储焊盘坐标，`_top_copper_gerber` 却把焊盘和电极一起交给按**左下角**解释的 `_rect_points`。
  - 结果是每个焊盘在最终（已旋转的）坐标系里都被平移了 (+w/2, +h/2)。
  - 走线总是接在焊盘朝向板体的那条边上：
    - 尾部朝 bottom/left 时，平移方向与走线方向一致，焊盘仍然连着走线；
    - 尾部朝 top/right 时，板体位于 −Y/−X 一侧，平移方向背离走线，焊盘与自己的走线脱开。
- **实测（默认 12×32）**：

  | 尾部方向 | 连通性 | 焊盘到相邻网络走线 | 焊盘到板边 | 触点暴露情况 |
  | --- | --- | --- | --- | --- |
  | bottom（默认）/ left | 44/44 相连 | **0.073 mm**（行板 11/12、列板 31/32 个焊盘，共 42 处，而且都在露出的开窗内） | 0.600 mm（规则 0.75） | 相邻焊盘的开窗合并成一个整窗，每个触点实际只露出约 57%（0.24/0.42 mm²），约 43%（0.18 mm²）被覆盖膜盖住；最外侧那个焊盘只露出 47.6%。开窗靠尾端的约 0.8 mm（距尾端 0.65–1.45 mm）没有铜 |
  | **top（UI 可选）/ right** | **44/44 全部开路**：走线末端到焊盘 0.573 mm；行板 GTL 有 24 个铜岛对应 12 个网络，列板 64 个对应 32 个 | — | **0.050 mm**（JLC：金手指距板边小于 0.2 mm 会被裁掉） | — |

  两种情况下引擎都返回 `ok=True`、没有警告，下载按钮可用。预览按引擎模型绘制，显示焊盘正常相连。
- **对照规则**：
  - 0.073 mm 低于 profile 自身的规则：行板 0.246 mm、列板 0.17 mm；
  - 也低于 JLC 对 18 µm 铜的线距能力 3.5 mil（0.089 mm），以及 JLC 的 "Exposed pad to trace ≥ 0.15 mm"；
  - 设计意图中的这个间距是 0.223 mm，满足上述所有规则。
- **影响**：
  - 按 UI 的 "Connector side: Top" 下单：两块传感器 100% 失效。
  - 按默认设置下单：触点错位，约一半接触面积被覆盖膜盖住，相邻网络间距低于工艺能力。
- **修复**：
  - 导出时把焊盘写成以中心为基准的矩形，或在中心位置闪一个矩形光圈（D03）。
  - 增加回归测试，覆盖 4 个方向 × 2 种 role_mapping。测试解析导出的 GTL 并检查：铜连通分量数等于网络数；每个焊盘与自身走线重叠；不同网络的间距不小于规则值。
  - 已验证：只修这一处（变异体 a），4 个方向上的几何差异全部消除，焊盘到相邻网络恢复为 0.223 mm。

#### C2 列板最外侧电极和覆盖膜开窗压到甚至越过板框，DRC 仍判通过

- **来源**：编排者线索、GEO-2、DRC-1、GERBER-3、SWEEP-2、AGENT-2、TESTS-6、REF-3、CRIT-3
- **验证**：全部确认。至少 5 个 agent 用不同方法复现，数值一致到 1e-6 mm。
- **位置**：
  - `engine/core.py:715-728`：外形从 `[0, active_y]` 直接连到第一个偏移点；
  - `:566`：板体预留的下边距从未被使用；
  - `:1026-1241`：DRC 不检查电极和开窗。
- **机制**：列板外形从板体侧边的点 `[0, active_y]`（右侧对称）直接连到"外侧走线末端的 0.385 mm 法向偏移点"。这条走线的末端恰好是最外侧电极底边的中点，所以这段板框正好从最外侧电极的外下角下方擦过。
- **实测**：

  | 列数 | 电极铜到板框 | 覆盖膜开窗 |
  | --- | --- | --- |
  | 32（默认） | 0.155 mm | 距板框 0.037 mm |
  | 17 | 0.062 mm | 越出板框 0.046 mm |
  | 16 | 0.039 mm | 越出板框 0.066 mm |
  | 8 | 0.018 mm | 越出板框 0.084 mm |
  | 4 / 2 | 0.0079 / 0.0026 mm | 越出板框 |
  | 1 | **0.000 mm**（电极底边落在板框上） | 越出板框 0.100 mm |

  - 节距较小时问题更严重。最外侧 deck 走线的 x 落在外侧电极中心以外，最后一段入口走线斜向外上方；于是第一个包络点被推到 active_y 以上，那段板框直接切进电极的外下角。例如 18 列、节距 1.3 mm，或 20 列、节距 1.2 mm 时，导出的 GKO/GTL 中电极铜伸出板框，引擎仍判 `ok=True`、没有警告。
  - 在 1–32 列 × 节距 0.6–3.0 mm 的网格中，有 4211 个被引擎接受的列板：
    - 4115 个（97.7%）电极距板框小于 0.2 mm；
    - 318 个电极触及或越过板框，涉及 1–27 列；
    - 144 个电极铜伸出板框，最多 0.0091 mm。
  - 在另一组 148 个引擎判为 ok 的变体中：全部电极到板框小于 0.75 mm，105 个开窗越出板框。
- **对照规则**：
  - profile 自身：铜到板边 0.2 mm，有效区边距 0.75 mm（另外三条边都满足）；
  - JLC 激光外形：铜到板边 ≥ 0.3 mm，外形公差 ±0.1 mm。
- **影响**：
  - 常见的 16 列及以下设计，电极铜离切割线只有 0–0.04 mm，切割公差会削掉电极角。
  - 开窗开到板边，会在切割边露铜。
  - 默认板也违反 profile 自己的规则，而引擎、预览和 UI 都显示通过。
- **修复**：
  - 在有效区下方保留真正的下边距。例如在 y = active_y − 0.75 处加一条水平板边，让包络与它相接；或者直接用 `buffer(union(外侧电极, 外侧走线), 间距)` 的外边界作为外形。
  - DRC 增加电极、焊盘、开窗到板边的检查。
  - 只改 profile 修不好这个问题，CRIT-3 已经验证过。

#### C3 连接器尾部几何与阅读板连接器不兼容

- **来源**：REF-1、CRIT-1、VERIFY-REF2-1
- **验证**：
  - REF-1 部分确认，维持严重。更正两点：触点行是居中的，所以"对称裁边后触点偏 0.4 mm"不成立；THD0515 实际要求 4.00 mm 触点、宽度公差 ±0.07 mm。
  - CRIT-1 用一手资料（BOM、厂商图纸、JLC 零件数据）复核确认。
- **位置**：`engine/core.py:458-459`、`:464-465`、`:569-570`、`:598`；`profiles/jlc_fpc_standard_v1.json:26-32`
- **阅读板上的连接器**（据 `flexitac/` 与 `new_reading_board_design/` 下的 BOM）：

  | 位号 | 型号 | 用途 |
  | --- | --- | --- |
  | FPC1 | TXGA FFC05001-16SBB124W5M | 16 路 SR，接行板 |
  | FPC2 | THD THD0515-32CL-SN | 32 路 SC，接列板 |

  两者都是 0.5 mm 节距、**底接触**、适配 0.3 mm 厚的 FPC。
- **连接器图纸要求**：
  - THD0515 的 "Applicable FPC" 图（LCSC C283153 数据手册第 4 页；矢量图，没有文字层）：宽 0.5×(N+1) ± 0.07 mm；触点从尾端起 **4.00 mm**；尾端 2-R0.30 圆角；0.30 mm 厚区长 6.00 mm。
  - 16 路连接器图纸：宽 0.5×(n+1)；触点 ≥ 3.00 mm；厚 0.30 ± 0.03 mm。
- **参考设计**（已被 JLC 接受的原始包）：12 pin 尾宽 6.500 mm，32 pin 尾宽 16.500 mm；触点 0.3×3.0 mm，距尾端分别为 0.405 mm 和 0.5 mm。
- **生成器的尾部**：
  - 尾宽 = 0.5×N + 1.3 = **0.5×(N+1) + 0.8 mm**：32 路为 17.3 mm，超出 THD 上限 0.73 mm；12 路为 7.3 mm。
  - 触点 0.3×**1.4 mm**，距尾端 0.75 mm。审查时受 C1 影响，导出后实际位于距尾端 1.45–2.85 mm 处；C1 修复后，导出位置回到设计值 0.75–2.15 mm。但按图纸要求，触点长度和起点仍不合格。
  - 尾端是直角，补强片从尾端内缩 0.25 mm。
- **profile 无法表达合格的尾部**：`pad_edge_clearance_mm` 同时决定尾侧边距、尾端边距和行板走线到板边的距离。把它改成 0.35 并把触点加长到 4.0 mm 后，所有行板都报 `E_ROUTE_EDGE_CLEARANCE`。
- **影响**：
  - 默认 32 路列板尾部宽 17.3 mm，THD0515 要求 16.5 ± 0.07 mm，插不进去。
  - 默认 12 路行板尾部宽 7.3 mm，比阅读板上 16 路 TXGA 连接器要求的 8.5 mm 窄 1.2 mm，问题在于路数和横向对位。"宽 0.8 mm"这个规律是 N 路尾部配 N 路连接器时的情况。
  - 两块板的触点长度和起点位置，都不满足两种连接器的图纸。
  - 系统里没有任何连接器模型或检查，也不会给出警告。
  - 应用与这块阅读板的对应关系，是从仓库里的 BOM 推断出来的。不过参考设计的尾部本身就采用 (N+1)×0.5 mm 的宽度和 3 mm 触点，独立印证了同一标准。
  - 阅读板的行接口是 16 路，默认设计只有 12 行，需要产品层面做决定（见第 6 节）。
- **修复**：
  - 在 profile 中加入连接器模型：节距、路数、宽度 = (N+1)×节距、边到首触点中心 = 节距、触点从尾端起 3–4 mm、R0.3 圆角、目标厚度，以及与尾端和侧边齐平的固定长度补强区。
  - 由这个模型生成尾部并做校验。
  - 在导出的 GTL 上做尾宽和触点位置的回归测试。

  - `:579-583`：合并段高度固定；
  - `:661`；
  - `:985-1023`：逐顶点偏移；
  - `:206`：输入允许 0.6–10 mm。
- **实测可行上限**（pitch_x，12 行）：

  | 列数 | 能生成的最大节距 |
  | --- | --- |
  | 1–10 | 整个范围（到 10 mm）都可以 |
  | 11 / 12 / 13 / 14 / 15 / 16 | 9.261 / 7.866 / 6.881 / 6.149 / 5.584 / 5.080 mm |
  | 17 / 20 / 24 / 28 / 32 | 3.618 / 3.173 / 2.725 / 2.410 / 2.177 mm（槽高 4 mm 时；行数很少时槽高变为 1.5 mm，上限升到 4.500…2.504 mm） |

  - 在均匀抽样的合法设计中，35.5% 要到完整生成之后才被 DRC 拒绝。换一种抽样方式是 44.1%；只看双 bank 模式则是 79.5%。
  - 默认 12×32 在节距 2.16–2.17 mm 以内能通过，从 2.18 mm 起失败。也就是说，"把节距放大"这种直觉上的放宽反而会失败。
- **根因**：
  - 入口段（16 mm）、合并段（16/12 mm）、单 bank 过渡段（约 7.4 mm）的高度都是固定的，不随横向位移缩放。
  - 节距变大后入口斜角变陡，`_offset_polyline_away_from_x` 在 deck→入口拐点处的逐顶点偏移量塌缩，可用公式 0.385·cos(φ−ψ) − 0.127 精确预测。
  - 结果是先触发 `E_ROUTE_EDGE_CLEARANCE`，接着触发 `E_ROUTE_CLEARANCE`。
- **报错的问题**：
  - 错误的 field 写的是 `boards.columns.routes`，但结果里实际的键名是 `boards.column`。
  - 消息只给出网络名和内部间距，没有说明该调哪个输入、调到多少。
- **影响**：32 列×2.5 mm、24 列×3 mm、16 列×6 mm 这类常见的触觉传感器参数都被拦下。用户或 agent 只能盲试，每试一次约 1 s。
- **修复**：
  - 让过渡段高度随横向位移缩放，并限制斜角。
  - 改用真正的多边形 offset，或给 deck 拐角倒圆。
  - 生成前做可行性预检，给出字段级的上下界，例如 `matrix.pitch_x_mm ≤ 2.16`。
  - 或者按 lane 模式收窄 profile 的允许范围。

#### H2 所有预览都是 Gerber 的上下镜像，而且预览不是由导出文件生成的

- **来源**：UI-1、UI-2、UI-8、GERBER-9（验证时升为中）
- **验证**：确认。依据是 Chromium 截图与 gerbonara 标准渲染的对比。
- **位置**：`engine/core.py:1434-1439`、`:1472-1479`；`web/app.js:41-42`、`:80-81`；`web/styles.css:19`；`exporters/direct_gerber.py:364-365`

- **影响**：预览会误导出线方向和引脚顺序。如果用户为了"让预览里的尾巴朝下"而选 Top，恰好踩中 C1 中全部开路的那种情况。（2026-10-13 更新：选 Top 不再导致开路，但做出来的板子尾部实际朝向与预览相反。严重度仍为高。）
- **修复**：

#### H3 列板的铜到板边规则（0.2 mm）低于 JLC 柔性板要求（0.3 mm），且只改 profile 无法修正

- **来源**：REF-3、VERIFY-GERBER-1、VERIFY-SWEEP-2、CRIT-3、SWEEP-11
- **验证**：确认。编排者已核对 JLC 能力页原文："Laser Outline ① Copper to board edge ≥ 0.3mm ② Copper to slots ≥ 0.3mm ③ Outline tolerance: ±0.1 mm"。
- **位置**：`profiles/jlc_fpc_standard_v1.json:49-50`；`engine/core.py:706`、`:1170-1177`、`:1187`
- **实测**：
  - 所有能生成的列板，走线铜到板边都在 0.195–0.258 mm 之间，默认为 0.206 mm。

  - 参考设计保持在 0.3476 mm 和 0.342 mm。
  - 行板（0.773 mm）和槽（0.623 mm）满足要求。
- **为什么只改 profile 不够**：

- **修复**：
  - 铜到板边、铜到槽的规则至少设为 0.3 mm，并注明来源和日期。
  - 包络偏移量由规则推导出来。
  - 配合 C2 和 H1 的结构性修改一起做。

#### H5 计划中的"验证门"大部分没有实现，`ok=true` 不等于可以制造

- **来源**：TESTS-6、GEO-4、DRC-7、VERIFY-GEO-1、AGENT-2
- **验证**：确认。
- **计划门禁的落实情况**：`docs/IMPLEMENTATION_PLAN.md:84-98` 列出 7 项门禁。

  | 状态 | 门禁 |
  | --- | --- |
  | 已实现（1 项） | 尺寸 / 方向 / 模板 |
  | 部分实现（2 项） | 矩阵适配（只覆盖 >16 列）；间距和边距（只检查走线） |
  | 隐含（1 项） | 连接器容量 |
  | 缺失（3 项） | 电极、连接器、外形、槽、覆盖膜、补强之间的干涉；网络连通；上下板对准与扫描映射 |

- **具体后果**：
  - API 允许两块板各自设方向。16 种组合中有 8 种会让行电极和列电极**平行**，根本形成不了矩阵，却仍返回 `ok=True`，没有警告。UI 只能选同一个方向，所以这种情况只能经 API 触发。

- **修复**：做一套整板 DRC，并对导出物也跑一遍：
  - 电极、焊盘、走线相对外形、槽和其他网络的间距；
  - 开窗和补强片在板内；
  - 网络连通；
  - 外形是否简单、有无尖角；
  - 两块板有共同的装配坐标且电极互相正交。

#### H6 未知、拼错、被包裹或取值非法的字段被静默丢弃，照常生成默认设计

- **来源**：AGENT-1、SWEEP-6、SWEEP-7
- **验证**：确认。AGENT-1 有一处更正：`connector_side` 和 `scan_order` 的非法值会报错，只有 `row_fpc_position` 的非法值会被静默忽略。
- **位置**：`engine/core.py:313`、`:363-372`、`:412-435`
- **实测**：

  | 请求 | 结果 |
  | --- | --- |
  | `{"matrix":{"colums":20}}` | 仍是 32 列，`ok=True`，可以导出 |
  | `{"design":{...}}`、`{"params":{...}}`、`{"Matrix":{...}}` | 得到默认 12×32 |
  | `row_fpc_position: "Bottom"` 或 `"middle"` | 保持 top=rows，不报错 |
  | 同时给 `scan_order` 和 `channel_order` | `scan_order` 被忽略 |
  | 把整个 `/api/generate` 结果 POST 到导出接口 | 返回**默认设计**的 Gerber，与 `{}` 的结果逐字节相同 |

- **修复**：
  - 拒绝未知键和包裹层，返回 `E_UNKNOWN_FIELD` 并带上 JSON 路径。
  - 拒绝非法的别名值，并报告哪些别名被应用、哪些被覆盖。
  - 导出响应回显规范设计的摘要，例如放在响应头里。

### 3.3 中（Medium）

#### M1 列板 PI 补强片越出板框，且覆盖了整个尾部和合并段

- **来源**：GEO-3、DRC-3、GERBER-4、SWEEP-4、TESTS-7、REF-8、REF-9、VERIFY-DRC-2。验证者对等级有分歧（高/中），这里取中。
- **越界情况**：
  - 100% 的列板补强片越出外形，默认情况最多越出 0.159 mm，位置在尾部肩部缺口处和合并段两侧；所有情况中最多越出 0.265 mm。
  - 1 列时有 6.23 mm² 的补强片在板外。
- **补强范围**：
  - 补强片是"尾部 + 合并段"的矩形内缩 0.25 mm。默认列板为 16.8×22.5 mm，并随尾长增长：尾长 40 mm 时变成 55.5 mm。
  - 尾端和两侧却各留了 0.25 mm 不补强。
- **参考设计的做法**：
  - 连接器补强与尾端、两侧齐平，长度固定：12 pin 为 10.668 mm，32 pin 为 4.663+0.854 mm。两种连接器图纸都要求 0.30 mm 厚区长 6.00 mm。
  - 在扇出区另有大面积 PI 补强：12 pin 约 24.1×7.3 mm，32 pin 约 20.1×14.8 mm。这些补强在原始导出里是 0.1 mm，在后来被接受的上传包里统一改成了 0.2 mm。
  - 参考设计的补强本身也略微越出外形，最多约 0.205 mm，而且被 JLC 接受了。
- **对越界问题的判断**：仅就"越界"而言，JLC 很可能会裁剪处理（这是推断），风险低于最初的估计。真正的差异有以下几点：
  - 生成器只有一块 0.2 mm 的矩形补强，覆盖整个合并段；
  - 这块补强随尾长增长；
  - 与尾端和两侧不齐平；
  - 导出器无法输出多种厚度的补强（见 M7）。
- **影响**：
  - "加长尾部"得到的是更长的刚性段，而不是更长的柔性段。
  - 尾端不齐平会影响插入。
  - JLC 工程审查可能要处理越界的补强。
- **修复**：
  - 补强片改为固定长度的连接器区，与尾端和两侧齐平，长度按连接器图纸确定，并裁剪到板内。
  - `stiffener_end_clearance_mm` 要么实现，要么删除。

#### M2 尾部根部有 47° 的 V 形缺口和毛刺，颈部比尾部还窄

- **来源**：GEO-6、DRC-6、TESTS-7、DRC-13、VERIFY-GERBER-2
- **缺口与毛刺**：
  - 合并段包络的最后一个偏移点落进了尾部矩形内。默认左侧这个点在 (24.354, 6.831)，深入尾部 0.554 mm，低于尾部上沿 0.169 mm。
  - 随后外形又跳回 `[tail_x, merger_base_y]`，由此形成一个 47° 的内凹 V 形缺口（反射角 313°）和一个 73° 的尖角毛刺，左右对称。
- **颈部**：
  - 尾部上方的最窄截面总比尾部窄 0.94–1.03 mm，默认是 16.358 mm 对 17.3 mm。
  - 1 列时是一段 0.77 mm 宽、19.75 mm 长的细颈，而尾部宽 1.8 mm。
- **圆角**：整块板没有任何圆角，槽角和行板尾根都是尖角。
- **影响**：
  - 柔性板上的尖锐内角是撕裂的起点。
  - 在目前的设计里，3 列及以上的板，缺口完全落在 0.2 mm 补强区之内；补强片正是在这个缺口处越界的（M1）。所以眼下的撕裂风险被补强掩盖了。但一旦按 M1 的建议把补强缩短到连接器区，缺口就会落在柔性弯折区里，所以两者要一起修。
  - 1–2 列板的细颈越过了补强片的末端，在机械上很脆弱。
- **修复**：
  - 包络在 y ≥ merger_base_y 处截断，并与尾部边相切连接，或者从尾部宽度开始做偏移。
  - 全外形加圆角，并加最小颈宽规则。

#### M3 装配预览的叠放顺序与默认 role_mapping 相反，翻转板 X 位置偏移，旋转后翻转轴不对

- 垂直方向的配准是正确的（误差 ≤ 0.002 mm）。
- **修复**：
  - 叠放顺序、翻转哪块板和图例都由 `physical_side` 决定。

  - 翻转轴取实际的电极长轴。
  - 配合 H2 统一坐标系。

#### M4 修改表单不会让上次的结果失效，下载到的是旧设计

- **扫描顺序只是元数据**：
  - `channel_order` 只改 JSON 中的 `pin` 字段。升序和降序的 Gerber ZIP 逐字节相同，只有 build_id 不同。
  - Gerber 里没有网络或引脚属性，没有丝印，也没有 pin 1 标记。
- **必须翻面的尾部**：
  - 两块 FPC 铜面相对叠放，所以两条尾部的铜面朝向相反。
  - 而阅读板上的两个连接器都是底接触，并且同面同向贴装（据 FlexiTac 贴片坐标）。
  - 所以必须把一条尾部翻面才能插入，而翻面会反转它的触点顺序。当前的扫描顺序控件表达不了这一点，应用也没有提及。
- **修复**：
  - 导出"taxel →（行、列、连接器引脚）"的映射表，以连接器的 pin 1 和插入面为基准定义引脚号，并加上 pin 1 标记。
  - 要么让扫描顺序真正改变铜皮；要么把它改名为"固件索引顺序"，并移出制造用的 build_id。

#### M6 溯源与身份标识不可靠

- **状态（2026-10-13）**：仍存在，并且有了一个具体后果。C1 修复前后的 ZIP 具有相同的 build_id 和文件名，只能靠 SHA-256 区分。导出器版本已升为 0.1.1，写在 Gerber 的 `TF.GenerationSoftware` 和审查包的 `exporter` 字段里，可以据此识别旧包。但 build_id 本身仍不包含导出器版本。
- **来源**：GERBER-8、GERBER-11、SWEEP-10、UI-7、UI-17、TESTS-10、TESTS-17、AGENT-9、VERIFY-SWEEP-3、VERIFY-TESTS-1、VERIFY-AGENT-2。确认并扩展了 10-11 审查第 4 条。
- **build_id 的构成**：`build_id` = slug + sha256(设计 + profile 的 id/revision) 的前 12 位。
  - profile 内容变了而 revision 没变时，build_id 不变。
  - 生成器版本、导出器版本、源码版本都不包含在内。
- **JSON 数字写法会改变身份**：`2` 和 `2.0` 得到不同的 design_sha256。浏览器默认构建的 ID 是 `tactile-fpc-12x32-805a37a1c806`，文档记录的默认 ID 是 `…42b62b433302`，但两者的 Gerber 逐字节相同。
- **审查包不完整**：
  - 缺少验证报告、profile 及其摘要、生成器版本、源码修订。
  - 不包含 Gerber ZIP 本身，只有它们的哈希；反过来，Gerber ZIP 里也没有 build_id 或设计哈希。
- **下载文件名**：
  - HTTP 下载名只用 slug，不同设计会重名，默认名都是 `tactile-fpc-12x32-…`。
  - 全中文名称会全部变成 `tactile-fpc`。
  - manifest 里记录的文件名与实际下载名对不上。
- **修复**：
  - 身份 = 规范化后（数字格式统一）的设计 + profile 摘要 + 生成器和导出器版本 + 源码修订。
  - 审查包写入验证报告和 profile。
  - 下载名使用 build_id，ZIP 内写入 manifest。

#### M7 profile 并不是唯一的事实来源，硬编码的值会覆盖或绕过它

- **来源**：CRIT-2、DRC-11
- **导出器硬编码补强参数**：
  - 导出器把 0.2 mm、PI、底面写死，GBSL 文件名和 `jlcpcb.json` 里的厚度也写死。
  - 把 profile 改成 JLC 同样提供的 0.1 或 0.25 mm（参考设计也用过 0.1 mm）后，生成时 `ok=true`、UI 显示新值，导出时却返回 422。
  - JLC 的示例是：0.11 mm 的 FPC 要配 0.3 mm 厚的连接器时，宜用 0.225 mm 补强。这个厚度同样输出不了。把它套用到本项目所用的基材属于外推，但方向是一致的。
- **profile 键不起作用**：
  - `maximum_channels_per_lane` 没有作为上限执行。
  - `trace_pitch_mm` 只用于显示。
  - `stiffener_end_clearance_mm` 无效。
- **硬编码的规则**：
  - 引擎里：焊盘间距阈值 0.2、槽宽下限 4.0、0.04 mm 余量、0.005 mm 容差、槽高的夹取范围。
  - UI 里：规则说明文字。
- **改 profile 的规则值也不受保护**：把 `active_edge_clearance_mm` 改到 0.3 后，电极距板框只有 0.013 mm，仍然 `ok=true`。
- **修复**：
  - 导出器从每个补强对象读取参数，并支持多块补强。
  - 把硬编码规则移进 profile，UI 文字由 profile 生成。
  - 删除或实现无效的键，并对 profile 本身做一致性校验。

#### M8 外形偏移算法不是真正的 offset

- **来源**：DRC-5、GEO-8
- **事实**：
  - `_offset_polyline_away_from_x` 的做法是"沿中心差分切线的法向移动每个顶点"，没有任何斜接或倒角处理。
  - 代码注释说它是 "miter-limited"、保证 "0.350 mm 最小值"，两处都与实际不符。
  - 默认列板在 deck→入口拐点处只偏移了 0.3329 mm（目标 0.385，差 13.5%），铜到板边的余量只剩 5.9 µm（0.205897 对 0.200）。
  - 这个偏差正是 H1 中双 bank 最大节距的决定因素。
- **修复**：用真正的多边形 offset（buffer 后取边界），或在拐角处加圆弧，并修正注释。

#### M9 没有最小电极宽度，也没有板尺寸上限

- **来源**：SWEEP-5、VERIFY-SWEEP-4
- **电极宽度**：
  - 10 µm 宽的电极也会被导出。
  - 宽度 ≤ 5e-7 mm 时 `ok=True`，但取整后变成零宽，导出失败。
  - JLC 对 18 µm 铜的最小线宽是 0.089 mm。
- **板尺寸**：
  - 没有板尺寸检查。两次独立的均匀抽样中，能生成的设计里分别有 8.3% 和 7.3% 超过 JLC 常规的 234×490 mm，1.7% 和 2.4% 超过 250×600 mm 的绝对上限。
  - 例如 64 行×10 列、节距 10 mm、尾长 80 mm，会生成 134.55×721.25 mm 的行板，只给出一条占空比警告。
- **修复**：在 profile 中加入最小电极宽度和最大外形尺寸，并在校验时执行。

#### M10 没有电测或网表数据

- **来源**：GERBER-5（部分确认）
- **事实**：
  - 焊盘是 G36 区域（没有 flash），没有 X2 网络/焊盘属性。
  - 也没有参考导出物里的 `FlyingProbeTesting.json` 或 IPC-D-356。
  - 如果有设计网表，CAM 或飞针测试本可以发现 C1 的开路，但发现不了 0.073 mm 的间距问题。（2026-10-13 更新：C1 已修复，这里不再是现实中的例子，但缺少网表的问题依然存在。）
  - JLC 接受只有 Gerber 的上传。
- **修复**：输出 IPC-D-356 或 EasyEDA 风格的 `FlyingProbeTesting.json`，并给焊盘加 `.P`/`.N` 属性。

#### M11 `derived-layout.json` 里同一组键名有两种锚点含义，且没有 schema

- **来源**：TESTS-11
- **事实**：
  - 焊盘的 `x/y` 是中心，电极和开窗的 `x/y` 是左下角，但键名完全相同（`x, y, width_mm, height_mm`）。
  - 没有 schema，也没有文档说明。
  - C1 正是这个歧义造成的。
- **修复**：统一为一种锚点含义，或改用不同的键名（如 `center_x`），并发布 schema。

## 4. 对 2026-10-11 审查结论的复核

| 上一轮的结论 | 本次结论 | 说明 |
| --- | --- | --- |
| 1. Gerber 焊盘坐标错位（X +0.150 / Y +0.700） | **确认，且严重性被低估** | 不只是错位。默认朝向下，焊盘到相邻网络只有 0.073 mm（低于 JLC 能力），约一半触点面积被覆盖膜盖住；UI 可选的 Top 朝向下，所有通道开路（C1）。**2026-10-13 已修复** |

### 9.4 需要产品决策的事项

1. **翻面方式与尾长**（N3、N27）。如果靠扭转翻面，补强之外的自由段至少要约 6 倍尾宽。建议让窄的行板做翻面板：16 pin 的行板尾宽 8.5 mm，尾长约 60 mm；32 pin 的列板直插。同时在应用里加上提示，例如尾部太短无法翻面的警告。

4. **参考设计的差异**：0.6 mm 电极和电极间开槽（L7）、对位特征（I1）、canonical 12×32 模板（I2）。
5. **装配视图的翻面轴**：按尾部轴还是按 D19 字面上的电极长轴（FV-UI-05）。
6. **其他**：浏览器中按角色设置扫描顺序；MCP/JSON-RPC 包装（M14）；覆盖膜窄条是否要向 JLC 确认；build_id 是否也要标识审查包的字节（N23）；pin 数等于通道数时是否按 null 计算身份；4 mm 最小槽宽和扇出不超出板体是否是有意的产品规则（2026-10-15 已决定：扇出可以比板体宽；两组走线保留，槽仍不窄于 4 mm，但用户没有单独回答 4 mm 最小槽宽是否有意，见 9.6）；两块板是否用不同的 `TF.SameCoordinates` 标识。
